## Generic GRPO engine combinations

Training exposes two backend families: Megatron and Automodel. Enabling both or neither raises an error; `automodel_cfg` is the current name and `dtensor_cfg` is retired: [Policy validation](/data/ycfeng/sota-engine/RL/nemo_rl/models/policy/lm_policy.py:162). The [generation registry](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/__init__.py:97) exposes four rollout engine families. These provide five variants when Megatron shared-model and dedicated-model modes are counted separately:

| Variant | Training engine | Student rollout engine | Sharing and weight update | Current full-vocabulary MOPD runtime |
| --- | --- | --- | --- | --- |
| Megatron shared model | Megatron | Megatron Core Inference | Same GPUs and workers, same training model tensors; phase switch without a second inference-model copy. | Source-supported with separated teachers; untested for this task. |
| Megatron dedicated inference model | Megatron | Megatron Core Inference, optionally `inference_optimized` | Same GPUs/workers, second model when layout/implementation differs; reshard updated training weights into it at every wake. | Source-supported with separated teachers; untested for this task. |
| vLLM model sharing GPUs | Megatron or Automodel | vLLM | Independent workers/models, sleep/wake and ZMQ plus CUDA-IPC weight refit. | SingleController rejects colocated vLLM. |
| SGLang model sharing GPUs | Megatron or Automodel | SGLang | Independent workers/models, memory release/resume and Ray CUDA-IPC bucket refit. | SingleController rejects co-location; current SC/Gym factory also rejects deferred SGLang load. |
| TRT-LLM model sharing GPUs | Megatron or Automodel | TensorRT-LLM `AsyncLLM` PyTorch backend | Independent workers/models, sleep/wake and ZMQ plus CUDA-IPC weight refit. | SingleController rejects co-location and has no TRT-LLM build branch. |

Generic GRPO co-location returns the same `RayVirtualCluster` for train and generation. Megatron reserves one worker group; other engines reserve two: [cluster allocation](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/grpo.py:1145). Backend pairings and transports are established by [refit constraints](/data/ycfeng/sota-engine/RL/docs/guides/refit.md:49), [factory Megatron/SGLang dispatch](/data/ycfeng/sota-engine/RL/nemo_rl/weight_sync/factory.py:169), [generic IPC dispatch](/data/ycfeng/sota-engine/RL/nemo_rl/weight_sync/factory.py:250), and [vLLM/TRT-LLM shared ZMQ path](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/grpo.py:3190). SGLang's Megatron-only restriction applies to separated refit, not colocated refit. Both TRT-LLM trainer combinations have executable functional scenarios: [Automodel](/data/ycfeng/sota-engine/RL/tests/functional/grpo_trtllm_automodel_colocated.sh:33), [Megatron](/data/ycfeng/sota-engine/RL/tests/functional/grpo_trtllm_mcore_colocated.sh:33).

These designs time-multiplex GPUs between training and student generation. They do not preserve simultaneous student training and generation on the shared GPUs. Generic **async GRPO** explicitly allows colocated generation only for Megatron: [async guard](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/grpo.py:5363). The TRT-LLM functional scenarios use `async_engine=true` but `grpo.async_grpo.enabled=false`: an asynchronous inference engine and asynchronous RL scheduling are different settings.

TRT-LLM colocated inference requires PP1, node-local TP, and no prefill/decode disaggregation: [placement guards](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/trtllm/trtllm_generation.py:67). SGLang requires its actual memory-release lifecycle; the shipped colocated config sets `sglang_cfg.sglang_server_config.needs_offload=true`: [config](/data/ycfeng/sota-engine/RL/examples/configs/grpo_math_1B_sglang.yaml:32), [lifecycle](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/sglang/sglang_generation.py:946). Its [refit source](/data/ycfeng/sota-engine/RL/nemo_rl/weight_sync/sglang_weight_synchronizer.py:26) explicitly describes CPU offload and staged memory restoration.

## The two Megatron variants

The dedicated model is selected automatically by [dedicated_inference_megatron_cfg](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/megatron/config.py:256). It compares resolved inference TP, PP, EP, expert TP, CP, and `transformer_impl` with training. If all match, generation uses the training model; otherwise the worker builds a second inference model and reshards at wake. Inference overrides live under `policy.generation.mcore_generation_config`. Inference CP is always one, so training CP greater than one forces the second-model variant: [config merge](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/megatron/config.py:201).

Both variants use Megatron training and Megatron Core Inference, not vLLM. The second model may use `transformer_impl=inference_optimized` while training retains Transformer Engine. See [effective generation config](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/megatron/megatron_generation.py:54), [dedicated model build](/data/ycfeng/sota-engine/RL/nemo_rl/models/policy/workers/megatron_policy_worker.py:4722), [wake/refit](/data/ycfeng/sota-engine/RL/nemo_rl/weight_sync/megatron_weight_synchronizer.py:151), and [shared parameter retention](/data/ycfeng/sota-engine/RL/nemo_rl/models/policy/workers/megatron_policy_worker.py:4961).

Dedicated-model setup rejects Torch FSDP2, VPP greater than one, PEFT, and draft models: [setup guards](/data/ycfeng/sota-engine/RL/nemo_rl/models/megatron/setup.py:2720). Its plan is created only with `load_optimizer=true`; frozen teachers therefore do not accidentally build the student's dedicated inference model. Native `refit_backend=nccl_m2n` is separated-only: [transport validation](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/megatron/megatron_generation.py:316). The shipped shared-model [SC example](/data/ycfeng/sota-engine/RL/examples/configs/grpo_math_1B_megatron_generation_colocated_single_controller.yaml:1) and [SC/Gym reshard functional scenario](/data/ycfeng/sota-engine/RL/tests/functional/grpo_megatron_generation_colocated_reshard_gym_single_controller.sh:115) use `refit_transport=mcore`; neither has been executed by this task.

## Current SingleController + NeMo-Gym + full-vocabulary MOPD constraints

1. **Student rollout co-location requires `backend=megatron`.** [config.py](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller_utils/config.py:1400) rejects every other colocated backend and requires `async_rl.min_groups_for_streaming_train == grpo.num_prompts_per_step`. The current recipe already sets that equality: [recipe](/data/ycfeng/sota-engine/RL/examples/configs/recipes/llm/mopd-r1distill-qwen-1.5b-7n8g-megatron-tp2cp4-pack-single-controller-fullvocab.yaml:20).
2. **Megatron Gym rollout needs `mcore_generation_config.expose_http_server=true`.** Token capture rejects a missing HTTP frontend: [generation guard](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/megatron/megatron_generation.py:669). [Setup](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller_utils/setup.py:1952) reserves frontend endpoints before the trainer/generation build; [SC guide](/data/ycfeng/sota-engine/RL/docs/guides/single-controller.md:43) documents the workflow. The KV-recompute flag must agree with `kv_cache_management_mode`: [Megatron settings validation](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/megatron/megatron_generation.py:211).
3. **Full-vocabulary MOPD requires Megatron training.** Teacher payload and reverse-KL kernels use vocabulary parallelism: [full config validation](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller_utils/config.py:1143). Automodel co-location support elsewhere does not make it usable for this full-vocabulary task.
4. **Teachers must remain separated.** Enabled SC MOPD requires `on_policy_distillation.non_colocated_teachers.enabled=true`, Gym, and nonempty teacher mappings: [MOPD guard](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller_utils/config.py:2068). Student cluster construction reserves teacher nodes first, then returns one student cluster for both student roles: [allocation](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller_utils/setup.py:463). There is no reachable all-five-teachers/student shared-GPU switch in this MOPD path.
5. **Changing to `examples/run_grpo.py` does not retain this full-vocabulary implementation.** Generic GRPO explicitly rejects `on_policy_distillation.full`, because it would otherwise train a different objective: [guard](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/grpo.py:834). Using colocated vLLM for this task requires additional implementation in SC or moving full-vocabulary support to another controller.
6. **Registry support is broader than SC/Gym construction.** SC `_build_generation` has vLLM/SGLang/Megatron branches, no TRT-LLM branch, and rejects deferred SGLang loading: [factory](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller_utils/setup.py:668). Gym asks for deferred generation load for non-Megatron engines: [Gym setup](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller_utils/setup.py:1971). This independently excludes current SC/Gym SGLang. The [SC guide](/data/ycfeng/sota-engine/RL/docs/guides/single-controller.md:742) marks Megatron/vLLM supported and SGLang/TRT-LLM untested.
7. **Dynamo and checkpoint-engine refit are not additional co-location schemes.** Both require separated generation: [Dynamo guard](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/__init__.py:226), [checkpoint-engine guard](/data/ycfeng/sota-engine/RL/nemo_rl/weight_sync/factory.py:143).

Colocated SC may keep completion-FIFO selection and the configured staleness policy. Whole-step batch assembly means collecting the required sample count, not collecting one specified dispatch batch. The [training loop](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/single_controller.py:2812) closes the rollout gate, suspends request deadline clocks, and sleeps Megatron before training; [blocks_training](/data/ycfeng/sota-engine/RL/nemo_rl/models/generation/megatron/megatron_generation.py:689) declares that requirement explicitly.

## Native distillation also co-locates the teacher, with different semantics

The separate native `distillation.py` controller supports a shared student-training/student-generation/teacher-scoring virtual cluster when colocated. It allocates [one shared virtual cluster](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/distillation.py:379) and builds an independent frozen [teacher Policy on train_cluster](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/distillation.py:515), with `init_optimizer=False`. Therefore this repository does contain teacher/student GPU time-sharing outside SC MOPD.

Its implemented generation construction branches are [Megatron and vLLM](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/distillation.py:541). Policy construction can select Megatron or Automodel, subject to the Megatron-generation requirement for a Megatron student trainer. The [shared-cluster placement](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/distillation.py:393) allows three colocated worker groups for vLLM. Megatron generation uses the student's workers; the teacher remains its own model, not shared student tensors. Inspecting the actual branch is more reliable than treating the four-engine registry as supported by this controller.

This is a single-teacher top-k-logit distillation workflow: it fetches teacher [top-k logits](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/distillation.py:978), with [topk_logits_k default 64](/data/ycfeng/sota-engine/RL/nemo_rl/algorithms/distillation.py:130). It does not establish support for the task's five-teacher full-vocabulary hidden-state payload workflow. Any older OPD prose claiming Megatron is entirely unsupported must yield to current implemented branches and guards; support is specific to the controller and objective.

## Decision and verification limits

Keeping the present full-vocabulary MOPD requires **Megatron training + shared-model Megatron rollout + separated Megatron teachers**, or **Megatron training + dedicated inference-layout Megatron rollout on the same GPUs + separated Megatron teachers**. With current TP2/PP4/CP1 training, a matching resolved inference layout/implementation chooses the first variant automatically; changing inference TP/PP or implementation chooses the second.

Both are source-supported options, not measured improvements. Switching vLLM to Megatron changes inference kernels, HTTP serving and KV lifecycle; requested-model parity and end-to-end throughput remain unverified. Native teacher co-location cannot substitute for this MOPD workflow by changing one flag.

Inspection used scoped `rg`, `nl`, `sed`, recipe and JSON reads, `git rev-parse HEAD`, and the local date. The host has `python3` at `/usr/bin/python3`; plain `python` is absent, and the first report-write attempt exited before creating a file. The retry used `python3` only for Markdown output. Acceptance checks identified exact engines, all generic pairings, both Megatron modes, current entrypoint restrictions, and teacher-sharing reachability. No production or GPU acceptance was inferred from these read-only checks.
